# Off Hours

เว็บแอปฝึกภาษาอังกฤษผ่านนิยายและแชท ออกแบบให้เปิดใน Safari แล้ว Add to Home Screen บน iPhone/iPad ใช้งานคนเดียว ไม่มี App Store

รายละเอียดแนวคิด โรดแมป และเหตุผลของการออกแบบทั้งหมดอยู่ที่แผนงานต้นฉบับ:
`แผนพัฒนาแอปฝึกภาษาอังกฤษผ่านนิยายและแชท (iPhone iPad).md` (บนเดสก์ท็อป) — ไฟล์นี้เป็นสรุปโครงสร้างโค้ดที่สร้างไว้แล้วเท่านั้น

## สถานะ: ขั้นที่ 1 สัปดาห์ที่ 1–2

### สัปดาห์ที่ 1 — เนื้อหาและคลังคำ ✅

- นำเข้าคลังคำจริงจาก NGSL Project — NGSL 2,809 + TSL 1,250 + BSL 1,744 รวมคำไม่ซ้ำ **5,228 คำ** (`npm run wordlists:import`)
- เขียนคัมภีร์เรื่อง (`src/features/story/storyBible.ts`) และตัวตรวจคำศัพท์ที่ใช้งานจริง (`src/features/story/validateEpisode.ts`)
- เขียน **ตอนที่ 1–3 ครบ** (`src/data/episodes/`) ผ่านตัวตรวจทุกตอน (`npm run episodes:validate`) — คำเป้าหมายครบ, ความยาว 800–1,200 คำ, สัดส่วนคำนอกคลัง ≤5%

### สัปดาห์ที่ 2 — หน้าอ่าน ✅

เกณฑ์ "เสร็จเมื่อ" ของสัปดาห์นี้คือ *อ่านจบหนึ่งตอนบน iPhone โดยไม่ต้องสลับไปแอปอื่น* จึงเน้นที่การทำให้ทุกคำในตอนกดดูความหมายได้ในแอป:

- **พจนานุกรมในตัว** นำเข้าคำนิยามภาษาอังกฤษแบบง่ายจาก NGSL/TSL (4,051 คำ) — แตะคำไหนก็ได้ในเนื้อเรื่องเพื่อดูความหมาย ไม่ต้องออกไปเปิดแอปพจนานุกรม
- **จับคำผันรูปได้** แตะ "approving" แล้วเจอ "approve" ผ่านรูปแปรจากคลังคำ และมีกฎตัดท้ายคำสำรองอีกชั้น
- **คำเป้าหมายได้คำแปลไทยตามบริบท** แสดงคู่กับคำนิยามอังกฤษในการ์ดเดียวกัน
- **เสียง** ฟังเสียงคำ และ **ฟังทั้งประโยคที่คำนั้นอยู่** ตามที่แผนกำหนด
- **เสียงบรรยายทั้งตอน** เล่นทีละประโยคพร้อมไฮไลต์ประโยคที่กำลังอ่าน ปรับความเร็ว 0.75–1.25× และเลื่อนจอตามอัตโนมัติ
- **จำที่อ่านค้างไว้** บันทึกประโยคล่าสุดที่อ่านถึง มีปุ่ม "อ่านต่อจากที่ค้างไว้" และปุ่ม "อ่านจบตอนนี้" ที่หน้าแรกแสดงสถานะแต่ละตอน
- **โหลดคลังคำครั้งเดียว** ไฟล์คลังคำ ~1.4MB ถูก fetch เฉพาะตอนที่เวอร์ชันคลังคำเปลี่ยน (ดู `CORPUS_VERSION`) ไม่ใช่ทุกครั้งที่เปิดแอป

ตัวเลขจากตัวตรวจ: แต่ละตอนแตะดูความหมายได้ **95% ของคำไม่ซ้ำ** ส่วนที่เหลือคือตัวเลข ชื่อวัน และคำนอกคลังทั้งสามรายการ (`npm run episodes:validate` จะพิมพ์รายการคำที่ยังไม่มีข้อมูลให้ดู)

ยังไม่ได้ต่อผู้ให้บริการ AI จริง — ตอนทั้ง 3 เขียนและตรวจด้วยสคริปต์ที่สร้างไว้ เพื่อพิสูจน์ว่า pipeline (คัมภีร์เรื่อง → เขียนตอน → ตรวจคำศัพท์ → เล่นในแอป) ทำงานได้จริงก่อนผูกกับ API ที่มีค่าใช้จ่าย

## เริ่มรันโปรเจกต์

```bash
npm install
npm run dev
```

เปิดที่อยู่ที่ขึ้นในเทอร์มินัล (ปกติ `http://localhost:5173`) ด้วย Safari บน iPhone/iPad ในเครือข่ายเดียวกัน เพื่อทดสอบ Add to Home Screen และฟีเจอร์เสียง (ดูหัวข้อความเสี่ยงท้ายไฟล์นี้)

### สคริปต์เนื้อหา (รันนอกเว็บแอป)

```bash
npm run wordlists:import     # อ่าน data/wordlists/*.csv → public/words.generated.json + data/wordlists/wordforms.generated.json
npm run episodes:validate    # ตรวจทุกตอนใน src/data/episodes/ (หรือระบุไฟล์เดียว เช่น episode-01)
```

| คอมโพเนนต์ร่วม | `src/components/` | `TappableText` (คำที่แตะได้ แบ่งเป็นประโยค), `WordCard` (การ์ดคำแปล/คำนิยาม), `NavBar` |
| ฟีเจอร์หน้าอ่าน | `src/features/reading/` | `text.ts` (ตัดย่อหน้า/ประโยค), `lookup.ts` (ค้นคำจากรูปผัน), `useNarration.ts` (เสียงบรรยายทีละประโยค) |
| คลังคำและรอบทวน | `src/lib/wordlists/`, `src/lib/srs/` | พาร์สไฟล์ NGSL/TSL/BSL จริง, เลือกคำเป้าหมาย (เฉพาะ TSL/BSL — NGSL เป็นฐานคำที่รู้แล้ว), คำนวณรอบทวน (ตอนนี้เป็น fixed-interval ไว้ก่อน ยังไม่ใช่ FSRS จริง) |
| เนื้อเรื่อง | `src/features/story/` | คัมภีร์เรื่อง (`storyBible.ts`), เรียกสร้างตอนผ่าน API (`generateEpisode.ts`, ยังไม่ต่อจริง), ตัวตรวจคำศัพท์ (`validateEpisode.ts`, ใช้งานจริงแล้วทั้งในแอปและสคริปต์) |
| ตอนจริง (3 ตอนแรก) | `src/data/episodes/` | เขียนและตรวจผ่านแล้ว — `episode-01.ts`, `episode-02.ts`, `episode-03.ts`, `index.ts` รวมเป็น `episodes[]` |
| สคริปต์เนื้อหา | `scripts/` | `import-wordlists.ts` (นำเข้าคลังคำ), `validate-episode.ts` (ตรวจตอน) — รันด้วย `tsx` |
| ตัวละครและแชท | `src/features/chat/characters.ts` | นิยาม 3 ตัวละคร (เพื่อนร่วมงาน/เพื่อนสนิท/แฟน) พร้อม system prompt และสำเนียง |
| ที่เก็บข้อมูล | `src/lib/db/` | IndexedDB ผ่านไลบรารี `idb` — words, episodes, characters, messages, progress, settings, meta |
| ชนิดข้อมูลหลัก | `src/types/` | `Word`, `Episode`, `Character`, `Message`, `Settings` |
| แชทตัวอย่าง | `src/data/sample.ts` | บทสนทนาตัวอย่างผูกกับตอนที่ 1 — ลบได้เมื่อมี `server/llm/chat-reply.ts` จริง |
| คลังคำที่ seed เข้าแอป | `public/words.generated.json` | ไฟล์สถิตที่หน้าเว็บ `fetch()` ตอนเปิดแอปครั้งแรก (ไม่ bundle เข้า JS เพราะไฟล์ใหญ่ ~1MB) |
| ฟังก์ชันฝั่งเซิร์ฟเวอร์ (โครง) | `server/` | ที่ที่คีย์ API ควรอยู่ — ดู `server/README.md` ก่อนเลือกโฮสติ้ง |
| คลังคำต้นฉบับ | `data/wordlists/` | ไฟล์ CSV จริงจาก NGSL Project ที่ดาวน์โหลดมาแล้ว + `wordforms.generated.json` (ใช้โดยสคริปต์ตรวจตอนเท่านั้น ไม่ส่งให้ไคลเอนต์) |

## สิ่งที่ยังไม่ทำ (ตามแผน)

- **ต่อผู้ให้บริการ AI จริง**: `src/features/story/generateEpisode.ts` และ `server/llm/*` ยังเป็นโครงเปล่า เลือกผู้ให้บริการ + โฮสติ้งก่อน (ดูหัวข้อ "เรื่องที่ต้องตัดสินใจก่อนเริ่ม" ในแผนต้นฉบับ) — ตอนที่ 1–3 เขียนและตรวจด้วยสคริปต์ไว้ก่อนเพื่อพิสูจน์ pipeline โดยไม่ต้องรอบัญชี AI
- **ตอนที่ 4 ขึ้นไป**: ต้องมีผู้ให้บริการ AI ก่อนถึงจะสร้างตอนถัดไปแบบอัตโนมัติได้ ระหว่างนี้เขียนตอนใหม่ด้วยมือตามแบบ `src/data/episodes/episode-03.ts` แล้วรัน `npm run episodes:validate` ตรวจก็ได้
- **รอบทวนแบบ FSRS จริง**: `src/lib/srs/index.ts` เป็น fixed-interval ไว้ก่อน
- **เสียง**: ยังใช้ `speechSynthesis` ของเบราว์เซอร์ (ไม่มีค่าใช้จ่าย) ยังไม่ได้เปลี่ยนเป็นไฟล์เสียงสังเคราะห์ผ่าน API, ยังไม่มีข้อความเสียงในแชท, ยังไม่มีภารกิจฟัง, ยังไม่มีการโทรสด
- **คำนิยามของคำสาย BSL**: NGSL Project ไม่มีไฟล์คำนิยามของ BSL คำที่อยู่ใน BSL อย่างเดียวจึงพึ่งคำแปลไทยตามบริบทของตอนเป็นหลัก
- **ไอคอนจริง**: `public/icon.svg` เป็นไอคอนตัวแทน ต้องทำ PNG จริงก่อนใช้งานบนเครื่อง (ดู `public/icons/README.md`)
- **ล็อกแอปด้วยรหัสผ่าน**: ยังไม่ทำ ต้องทำก่อนเผยแพร่ URL จริง เพราะใครเปิดลิงก์ก็ใช้เครดิต API ได้
- **ซิงก์กับคลาวด์**: `server/sync.ts` เป็นโครงเปล่า ตอนนี้ข้อมูลอยู่ใน IndexedDB ของเครื่องเดียวเท่านั้น
- **หน้าตั้งค่าครั้งแรก/วัดระดับภาษา**: ยังไม่มีขั้นตอนให้ผู้ใช้บอกว่ารู้คำไหนแล้วตอนเริ่มใช้ครั้งแรก (งานของสัปดาห์ที่ 3)

ลำดับการทำต่อ แนะนำให้ตามสัปดาห์ที่ 2–3 ของขั้นที่ 1 ในแผนต้นฉบับ (หน้าอ่านจริงบน iPhone จริง → สมุดคำศัพท์/ตั้งค่า/วัดระดับครั้งแรก) ก่อนค่อยเลือกผู้ให้บริการ AI เพื่อสร้างตอนที่ 4 เป็นต้นไป

## ความเสี่ยงด้านเทคนิคที่ต้องทดสอบก่อน

ทดสอบบน iPhone/iPad จริงตั้งแต่ตอนนี้ (ไม่ใช่แค่ในเบราว์เซอร์คอมพิวเตอร์):

1. เสียงอ่านของเบราว์เซอร์ (`speechSynthesis`) เล่นได้ปกติในโหมด Add to Home Screen หรือไม่
2. การขอใช้ไมโครโฟนทำงานหรือไม่ (ตัวรู้จำเสียงของ Safari ใช้ไม่ได้ในเว็บแอปบนหน้าจอโฮม — ต้องอัดเสียงแล้วส่งถอดเสียงบนคลาวด์เท่านั้น)
3. ข้อมูลใน IndexedDB ยังอยู่หลังไม่เปิดแอปหลายวัน (Safari อาจล้างข้อมูลถ้าพื้นที่เต็มหรือไม่ได้ใช้นาน — ได้ขอ `navigator.storage.persist()` ไว้แล้วใน `src/lib/db/index.ts` แต่ยังต้องทดสอบจริง)
